## Germany permit follow-up (October 2026)

This is a follow-up to the Germany batch of 5 October 2026. That batch could not read the German environmental impact assessment register (uvp-verbund.de and the state portals) because the register throttles every request. The files have since been collected into a local cache, and this run reads them.

How to work each plant:

1. Do the plant-level task first. It names the permit register summary file in `work/permits/germany/` and any other official notices. Read the summary, then the procedure page and the saved documents with `python scripts/fetch.py <url> --text`. A cached read returns at once. An uncached read of the register can take several minutes because the server refuses most requests and the fetcher waits and retries; let it run and never report the register as blocked.
2. The earlier findings for this plant are in `batches/germany/shards/<plant id>.json`. Read that shard before the unit blocks. For each "What to check" block, do not repeat the searches already done there. Report a unit value only when the permit documents or the other official notices add a value that the earlier shard did not have, or change one. If the documents confirm the earlier shard's value, say so in one sentence in the notes and do not stage the value again.
3. Cite the specific document (procedure page or PDF address), never the register home page or a search page. Run `url_verifier.py` on every cited address with the plant name and the value; register addresses verify from the cache.
4. Capacity is electric generating capacity in MW. German permit files usually state the thermal input (Feuerungswärmeleistung, FWL, MW thermal or MWth). That is not capacity; put it in the note only. Record electric capacity only when the document says MWel, elektrische Leistung, or Bruttoleistung in MW.
5. Permits and the lifecycle rules: an application or a public display means the project is at least announced; a preliminary decision (Vorbescheid) or a first partial permit (1. Teilgenehmigung) supports pre-construction only together with the operator's final investment decision; a permit alone never makes a unit under construction. A status change needs two independent publishers for green, so pair the permit file with the earlier shard's operator or press source where one exists.
6. Latest Activity follows the rule in the lifecycle reference: only for projects in development, shelved or with an inferred status, and only with a date at least a year old.

The two official register files are already downloaded. Read them with pandas instead of fetching them again:

- `/Users/baird/Dropbox/_git_ALL/_github-repos-gem/gogpt-researcher/work/sweep_germany/Kraftwerksliste_2026-06-26.xlsx`: the Bundesnetzagentur power plant list, data date 26 June 2026. Sheet `Gesamtkraftwerksliste`, header on row 8 (`pd.read_excel(path, sheet_name=0, header=7)`). Gas rows have `Energietraeger` equal to `Erdgas`. Match a GEM plant by `Anlagenbetreiber` (operator), `Bundesland` and capacity, not by name; GEM plant names are English and the register's `Anzeigename` is usually different. Status is in `Kraftwerksstatus` (exact strings and their GEM mapping are in the country note), start year in `Jahr_Inbetriebnahme`, closure year in `Jahr_Stilllegung**`, nameplate in `Bruttoleistung_MW`, net in `Nettonennleistung_MW`, technology in `Technologie_Stromerzeugung`.
- `/Users/baird/Dropbox/_git_ALL/_github-repos-gem/gogpt-researcher/work/sweep_germany/ZuUndRueckbau_2026-06-26.xlsx`: expected additions and closures, same data date. Sheet `Zu- und Rückbau einzeln`, header on row 6 (`header=5`): register number, operator, plant name, postcode, town, fuel, net MW, expected year of commercial operation. A unit listed here as expected in 2026 or 2027 is under construction or in trial operation according to the operator's legal report; that supports construction status and a start year, but confirm commissioning itself with the operator or press.

When you cite one of these files, use the download URL from the country note as the reference and say in the note which file, which data date and which row (operator and `Anzeigename`) you read. Run `url_verifier.py` on the download URL with the value, as for any other source.

The capacity tenders under the StromVKG law: the first round closed on 8 September 2026 and awards are due by 3 November 2026, so no award list exists yet. An owner's announcement that it bid, or that it plans to bid, is a Latest Activity entry with the press release as the source, not a status change. If you find an award list published after this brief was written, treat an award as a strong signal but keep the lifecycle rules: no permit and no construction means the status stays announced or pre-construction.

German-language sources are expected. Write every note in English. A short German quotation is fine when followed by its English meaning. Permits are usually BImSchG approvals published by the state environment office or the Regierungspräsidium; the town's or district's official notices (Amtsblatt) carry the dates.

Reading other blocked sites: the fetcher now opens a page in a real Chrome when nothing else gets past a bot check, and it remembers which sites needed that. energate-messenger.de, waz.de, waz-online.de and chemieindustrie-online.de all open this way now. Some sites are still out of reach: waerme.hamburg and hamburger-energiewerke.de block requests from outside Germany, and several old company domains are gone. For those, `url_verifier.py` checks saved copies in the Internet Archive. If the archive copy shows the value for a page that still exists, the live address stays the citation. If the page is gone, the verifier names the archived copy; use it only as a lead to a live source, and say in the notes when no live source was found. The country note's "Site access" section lists what each German site needs.
