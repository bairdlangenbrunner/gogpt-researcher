## Access, probed 2026-11-03

Two probes ran against the live sites before this plan was written. What they found governs the harvesters below.

- ODEQ: the old deq.ok.gov notice pages redirect to oklahoma.gov/deq and have no archived content. The "Permits for Public Review" table (`https://applications.deq.ok.gov/PermitsPublicReview/`) answers one anonymous GET with the whole table, no paging, 286 rows on the day (172 air); its certificate fails verification, so fetch with verification off. Each row links `permitinformation.aspx?id=N`. The documents come from the OnBase Public Access API (`https://okdeqonbaseexternal.databankcloud.com/pav/api`, anonymous JSON): `POST /CustomQuery/KeywordSearch` with `{"QueryID":262,"Keywords":[{"ID":"828","Value":"Horseshoe*"}],"QueryLimit":0}` (830 permit number, 829 division, 828 facility, 827 company, 312 county, 844 object id); a date-only query from 2015 returns 1,491 documents, earliest April 2016; `GET /Document/<url-encoded id>/?ViewerMode=PDF&ForceDownload=true` returns the PDF. Results carry the document type and date, not the facility. Full-text search is not licensed (403). Mustang and Oneta return zero documents. No feed; GovDelivery email only. No rate limit seen in about 45 requests.
- OCC: no anonymous scriptable search of current cases. The legacy search (`https://case.occ.ok.gov/ords/f?p=1003:202`, Oracle APEX) answers anonymously but holds cases before 2022 with numeric numbers; date searches return nothing. The current Electronic Case Filing site loads but its API answers 401 without a sign-in token (OpenID flow). The Laserfiche WebLink store (`https://public.occ.ok.gov/WebLink/`) is the way in, proven from a script on 2026-11-03 after Baird found that its "all imaged documents" search works in a browser: open `Welcome.aspx?dbid=0&repo=OCC` once for the session cookie, then post JSON to `SearchService.aspx/GetSearchListing` with any Laserfiche search string (a name search `{LF:Name="PUD2026-000073*"}` lists every filing of a cause, a field search on Case Number lists its imaged orders, a date range on ECF Docket Date with ECF Division PUD lists a month of orders). An electronic filing downloads as a text PDF from `ElectronicFile.aspx?docid=<id>&dbid=0&repo=OCC` with no cookie, so that is its citation; an imaged order gives OCR text from `DocumentService.aspx/GetTextHtmlForPage` or a real PDF through the export handler, and its citation is the `DocView.aspx?id=<id>` address. The exact calls are in `scopes/us-ok/coverage.json` under `occ-weblink`. The daily Public Utility Division docket PDFs (`https://oklahoma.gov/occ/court-dockets/docket-results.html`, files like `.../court-clerk/docket-results/2026/2026-10-29-pud.pdf`, about three years) download with plain fetch and extract cleanly; they list only matters set for hearing. The PUD reports folder holds the OCC copy of the OG&E 2025 IRP. OG&E's own IRP pages on oge.com are 404; the 2026 IRP PDF on ogeenergy.gcs-web.com needs the browser-fingerprint route. PSO's IRP page and PDFs load with plain fetch. Western Farmers, Grand River Dam Authority and OMPA home pages load. The SPP CSV is anonymous.

## Manual rules the run must follow (added 2026-11-03 after reading Amalia's ChatGPT instructions)

- The IRP naming rule: a unit that exists only in a utility's plan is `announced` with "IRP" in the unit name, at the utility's IRP placeholder plant where one exists. A project the utility has announced publicly gets the IRP box ticked and no suffix. When a later filing names the site and the unit, the placeholder unit is renamed, never duplicated.
- Data center phase grouping: identical engines with one timeline form one unit (count and per-engine capacity in the name, as `docs/reference/unit_conventions.md` says), distinct phases with different start years become separate units, and a permitted building is not a built one.
- The building and the generators are different things. A data center's status in the press (under construction, open) says nothing about its engines; the engines' status follows their own permit, construction and energization evidence. When counting, an EIA-860M generator row is one machine, not one GEM unit; the engines of one phase are summed into one unit.

## New tooling

Built 2026-11-04, each with an offline test (`tests/test_harvest_permits_oklahoma.py`, `tests/test_harvest_psc_oklahoma.py`, the `occ` tests in `tests/test_fetch_access.py`). Kept here as the spec. 1. `scopes/us-ok/harvest_permits.py --scope us-ok`. Writes `scopes/us-ok/work/permits/<plant_id>.md` per GEM plant, `_unmatched.md` for power-like facilities with no GEM match, `index.json`, and a dated snapshot of the table under `scopes/us-ok/work/permits/ppr/<date>.json`. Steps, in order:
   - GET the Permits for Public Review table with TLS verification off (requests `verify=False` or `curl -k`; `fetch.py` already records the host as `insecure_tls`). Parse the server-rendered table: Division, County, Company, Facility, Permit number, Tier, Type, Step (with comment dates), Staff, Status, and the `permitinformation.aspx?id=` object id. Keep every row (the water and land rows name data centers); mark Division AQD rows.
   - Match rows to GEM plants by company and facility name words, city and county, case-insensitively (the table mixes "Oklahoma" and "OKLAHOMA"). Names to expect: "OG&E" and "Oklahoma Gas and Electric", "PSO" and "Public Service Company of Oklahoma", "Western Farmers", "Associated Electric", "Grand River", "OMPA", "Tenaska", "Peoples Electric".
